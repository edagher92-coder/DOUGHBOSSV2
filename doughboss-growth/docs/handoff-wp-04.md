## Interface for later packages

- `DoughBoss_Growth_Attribution::for_subject( $type, $id )` returns `array( 'attribution' => array (camelCase keys of attribution-schema.ts), 'consent' => array( measurement, advertising, chosen, version ), 'captured_at' => 'Y-m-d H:i:s' UTC )` or `null` (no row). Everything is re-sanitised on read; a malformed stored row reads as empty and closed. `$type`: `payment_ref` (id `[A-Za-z0-9_-]{1,100}`), `order`, `enquiry`, `waitlist` (positive integer ids).
- WP-08: use `for_subject( 'order', $order_id )` and `for_subject( 'enquiry', $enquiry_id )`; `consent` is the snapshot taken when the visitor acted, and a row exists only when there was attribution or a consent flag worth keeping. No row means no consent: send nothing.
- `DoughBoss_Growth_Attribution::record_current( $type, $id )` stores the current visitor's consented cookie for a subject (WP-05 can call it with `'waitlist'`). `write_subject()`, `current_attribution()`, `consent_snapshot()` and `sanitise()` are public.
- Action `doughboss_growth_lead_recorded( $enquiry_id, $meta )` (fires once per new lead row; `$meta` = segment, company_name, landing_key, consent_marketing, consent_text_version; no email or name).
- WP-07 form contract, request parameters on `POST /doughboss/v1/catering/enquiry` (all optional): `dbgr_company` (text, 120), `dbgr_segment` (key, 40), `dbgr_landing_key` (key, 64), `dbgr_consent_marketing` (exactly `1`), `dbgr_consent_text_version` (letters, digits, `.`, `_`, `-`, 20). **Marketing consent is stored as given only when the box is exactly `1` AND a valid wording version is sent; otherwise it is stored as NOT given.** The stash is applied only when the enquiry's email matches the request's email, so a rejected request cannot leak fields into another enquiry.

## Decisions I made (flag them if you disagree)

1. **First touch wins** for 90 days; a later landing replaces the record only when it carries campaign parameters the visitor consented to. A direct first visit still records the landing path (measurement consent).
2. **Staff are not visitors.** A signed-in manager (`manage_doughboss`/`manage_options`) gets a closed consent snapshot, so a staff member keying an order or enquiry never attributes their own browser's cookies.
3. **A lead row is always written** when the enquiry hook fires (flag on): it holds the form's company/segment/consent even when the visitor rejected cookies (attribution is then `{}`). The `enquiry` attribution row exists only when attribution or consent is worth keeping.
4. **`referrerHost` is stricter than the TypeScript schema** (see contract change 1). 13 of the 106 oracle cases differ on that one field alone; the tests assert the difference set is exactly the host-rule cases.
5. **Caps are counted in Unicode code points.** zod 4 (4.6.5 here) counts code points, not UTF-16 units: 120 emoji are accepted, 121 are not. PHP and JS match; the fixture records the zod version.
6. **No server-set cookie.** Only the browser script writes `dbgr_attr`.
7. **`attribution` works only with the consent banner on** (no one to ask otherwise): the script is not enqueued and the server snapshot is closed. The tab shows this as a [CONFIRM] gap.

## [CONFIRM] gaps (also shown in Growth, Attribution)

- Privacy-policy wording: it must describe the `dbgr_attr` cookie (90 days) and that the source of an enquiry or order is stored with it.
- **Retention**: there is no automatic deletion of attribution or lead rows. Elie, with an accountant or solicitor, to set a period.
- **Privacy tools**: these tables are linked to enquiry and order ids but are not yet covered by the WordPress personal-data exporter and eraser (core's privacy class does not know them). Decide whether they need one before enabling.
- A Stripe Checkout redirect returns no `payment_intent` in `/payment-intent` (it returns `checkout_session`), and any payment id with characters outside `[A-Za-z0-9_-]` is refused: such an order uses the cookie at the moment the order is created.
- Marketing consent on a lead is recorded only with the wording version (WP-07 must send it).
