## What changed and why

1. **Paid-order confirmation email** (`includes/class-doughboss-emails.php`).
   - New stage `placed`, hooked on `doughboss_order_created` at priority 40.
   - It sends only when `$data['payment_status'] === 'paid'`, and the stored row is re-checked as paid.
   - It goes through the existing `deliver()` path: the atomic lock, the stage log (dedupe), the no-PII log lines and the optional staff copy.
   - The body comes from the pure `DoughBoss_Emails::placed_email()`. It is plain text in Australian English and uses stored figures only:
     - order number, and one line per item: qty × name (size), line total
     - options/modifiers (array `label` or string), any per-line note
     - subtotal, voucher/discount, delivery fee (when above 0), "Total paid", and "Includes GST of $x" (only when `tax` > 0)
     - order notes
     - pickup shop name ("Dough Boss <Shop>"), address and phone from the order's `location_id` row
     - the tracking link, or the existing fallback copy when no tracking page is configured
   - Toggle: `email_on_placed`, default ON. Admin: Settings > Real-time & Notifications. It uses a present-flag sanitizer (`email_on_placed_present`), so saving another tab never flips it.
   - **Behaviour change.** `send_confirmation()` (REST) no longer emails the *customer* when the `placed` stage was already sent for that order. The template confirmation is still the fallback if the `placed` email failed or is switched off. The shop-inbox copy is unchanged.
2. **Square partial refunds** (`reconcile_refund_event`).
   - On a `partial` settlement the handler now runs `GET /v2/payments/{id}` through the attempt's existing shop binding (`retrieve_payment_with_binding`).
   - Pure `payment_refund_state()`:
     - **full** needs the same payment id, payment status `COMPLETED`, and integer `refunded_money` in the attempt currency of at least `amount_minor`. A full result falls through to the existing "mark refunded" path.
     - **Anything else** sends one staff email to `orders_email` per refund id: order #, this refund, the running total and the amount paid. The email is built by the pure `partial_refund_notice()`, and an atomic autoload-off option marker prevents repeats. The webhook returns `partial` and the order stays `paid`.
     - **If the payment read fails**, the handler returns `retry` (500, so Square retries).
3. **Wallet buttons** (`mountWallets` in `public/js/doughboss-square.js`).
   - Each click runs `formReady()` synchronously: `form.reportValidity()` first, aborting with a visible message if the form is invalid. Then `request.update()` and `tokenize()` run in the same gesture, so Apple Pay's requirement holds.
   - A non-OK tokenize result, or a thrown/rejected one, shows a message in the existing status line (`db-pay-secure db-error`, `role=alert`). A cancelled sheet gets its own wording.
4. **Performance.**
   - (a) The Square Web Payments SDK is enqueued only when `is_order_page()` is true or the post contains `[doughboss_cart]`.
     - The ordinary `squarePayments()` path now loads the SDK on demand when `window.Square` is missing, through the existing exact-CDN loader (`loadApprovedSquareSdk`, which checks `CONFIG.sdkUrl` against the environment).
     - Approved pre-order links were already on-demand, so they are unchanged.
   - (b) `doughboss-shop-status.js` refreshes every 120 s instead of 45 s, and polling stops completely while `document.hidden` (`visibilitychange` resumes it).
     - **Deviation, deliberate.** Server pickup-hours evidence is valid for only 60 s, and the UI shows "Pickup hours unconfirmed" once it expires. While ordering is **open** and a shown status has expired, the script refreshes early, but never more often than every 30 s.
     - While ordering is paused (live today) the status copy needs no evidence, so the interval is a true 120 s.
5. **Order board wake lock.**
   - `navigator.wakeLock.request('screen')` runs when the board loads and again inside the "Enable sound" click. It is re-acquired on `visibilitychange`.
   - Only one request is in flight at a time. It is skipped while hidden and fails silently when unsupported or refused.
6. **Remember me** (checkout in `public/js/doughboss.js`).
   - An opt-in checkbox, "Remember my details on this device", stores only name, email and phone (trimmed, max 200 characters) in `localStorage` key `doughboss_remember_details`.
   - On load it fills only empty fields and shows as ticked when details are saved.
   - It saves on field `change` while ticked. This is not tied to submit, because the Square module intercepts submit. Unticking deletes the key.
   - Every storage access is in try/catch. A small CSS rule is added in `public/css/doughboss.css`.
7. **Housekeeping.**
   - (a) Square Loyalty "done" markers are now the transient `doughboss_sqloy_done_<id>` with a 30-day TTL. Orders have no meta table, so this replaces one permanent `wp_options` row per order. Legacy `doughboss_sqloy_<id>` options are still honoured.
   - (b) The Apple Pay domain file now lives in its own autoload-off option, `doughboss_square_apple_pay_domain_file`. The accessor is `DoughBoss_Settings::square_apple_pay_domain_file()`.
     - **Migrate on read:** the value is copied into the new option. The legacy key is stripped from `doughboss_settings` straight away only when no settings sanitizer is registered for the request (front end), and always on the next settings save.
     - The admin textarea reads and writes the new option. The key was removed from `defaults()`.
   - `uninstall.php` removes the new option, the loyalty markers (legacy and transient) and the partial-refund markers.
8. **Local SEO JSON-LD** (`includes/class-doughboss-seo.php`).
   - One `Bakery` node per active shop, from the pure `DoughBoss_SEO::location_node()`:
     - name "Dough Boss <Shop>", `PostalAddress` (with postcode)
     - `telephone`, `url` = /locations/, `servesCuisine` "Lebanese"
     - grouped `openingHoursSpecification`, `hasMap`, `parentOrganization`
   - Stored location fields and stored weekly hours win. The published facts in `shop_facts()` fill blanks only:
     - Revesby 7 days 6:30–14:30
     - Bankstown Mon–Fri 7:00–14:00
     - Roselands daily 8:00–15:00
   - The previous unverified `priceRange: "$"` was removed, and the type is now `Bakery` only.
   - Output is still on the front page and /locations/ via the theme's existing `doughboss_seo_relevant_page` filter.
9. **Theme/content.**
   - `/order/` gets its own title and description (open/paused wording). `/menu/` keeps "Dough Boss Menu | …". page-menu.php renders page-order.php, so `/menu/` now gets its own H1 ("Our menu.") and lede. The canonical for /menu/ is still /order/.
   - Hero alts:
     - The plugin manoush hero (feast photo, front page and catering) now uses "Dough Boss manoush and pies fresh from the oven" (new `image_alt` shortcode attribute).
     - Theme page heroes get accurate per-photo alts ("Dough Boss Sujuk Deluxe pizza fresh from the oven", "Dough Boss zaatar and cheese manoush fresh from the oven", and the feast alt on About). The manoush/pies wording would have been wrong on the pizza photo.
   - Catering: the theme hero description and the plugin `[doughboss_catering]` contact block both state "Pickup from Revesby · minimum N business days’ notice". N comes from the existing `catering_min_notice_business_days` setting (default 2). The "How much notice" FAQ answer now states the minimum.
10. Versions: plugin 2.48.0 (header, `DOUGHBOSS_VERSION`, readme stable tag and changelog). Theme 1.7.0 (`style.css` and `DOUGHBOSS_FINAL_VERSION`).

## NOT verified / open risks

- Nothing here ran against WordPress, MySQL, a mail transport, Square sandbox or a real browser. That includes the hook wiring, wp_mail, the admin save, wallet sheets, the wake lock and the SDK on-demand load.
- `refunded_money` semantics: this assumes Square counts only completed refunds there. Confirm in sandbox with two partial refunds that add up to the full amount.
- Partial-refund notices fire once per refund id. Square also sends `refund.updated` for a completed refund, but the marker prevents a duplicate.
- On a page that has `[doughboss_cart]` but is not the order page, the SDK still loads (by design). Pages with neither now load it on demand, the first time card fields mount.
- The `placed` email is sent synchronously inside the checkout request, just as `send_confirmation()` already was. Mail latency adds to checkout time no more than before.
- With "Send staff a copy of stage emails" ON (default OFF), the shop inbox gets both the `placed` copy and the existing confirmation.
- Legacy loyalty marker rows (`doughboss_sqloy_<id>`) from earlier versions remain until uninstall. They are harmless. To clean them, run `DELETE FROM wp_options WHERE option_name REGEXP '^doughboss_sqloy_[0-9]+$'` after a backup.
- The JSON-LD hours come from stored *pickup* hours when they are configured. If a shop's online-pickup hours differ from its trading hours, structured data shows the pickup hours. Check each shop's hours in DoughBoss > Locations.
