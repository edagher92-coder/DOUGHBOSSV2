# DoughBoss 2.49.0 + DoughBoss Final theme 1.8.0 (Claude)

## 15 Oct 2026, Claude, branch `overnight-2.48` from `f01bf4c` (2.48.0 / theme 1.7.0)

Status: **committed locally only. Not pushed, not deployed, not checked on staging or live.**

- Spec: the owner's front-end audit (`doughboss_frontend_fixes_for_claude.md`), P0 + P1 in full, P2 where safe.
- Payment, checkout, cart and order logic are unchanged. No Square, Stripe, Tyro or MPGS code was touched.
- DB version is unchanged (1.29.0). There is no schema change and no migration.
- New settings (both optional):
  - `b2b_email`: blank means the orders inbox.
  - `order_phone`: default `0297742286`.
- **Business rule (overrides the audit).** Catering is **pickup from Revesby only**.
  - There is no Bankstown/Roselands pickup chooser.
  - Public enquiries for other shops, or for delivery, are refused server-side.

## Done

### P0
1. **Menu search** (`public/js/doughboss.js`).
   - The `⌕` glyph is replaced by an inline SVG.
   - A clear (×) button appears once a query is typed (`aria-label="Clear search"`).
   - The native webkit cancel button is hidden so there are not two clear buttons.
2. **Double-escaped entities.**
   - `DoughBoss_Post_Types::plain_menu_description()` still decodes once. It now also repairs a stranded `&amp;` that stands alone as a word (for example "olives &amp; cheese").
   - New `plain_menu_title()` is used for menu item names and catering package names in REST.
   - Entity markup such as `&amp;lt;em&amp;gt;` is still never interpreted.
   - Note: the live 2.47 SSR and REST already showed Sujuk Special with a single "&". The audit's `&amp;` was not reproducible today. The fix covers stored double-escaping.
   - The integration test `tests/integration/wordpress-mysql.php` had expectations for decoding exactly once. Two of those cases now expect "&" (see Verification).
3. **No grey boxes.**
   - Photo-less items get a warm branded tile ("Dough Boss · Oven-baked" plus the category).
   - A photo that fails to load is swapped for the same tile.
   - Photo frames now sit on a warm dark ground while loading.
4. **Drinks** (any category matching `^drinks?`): a compact two-column list with no photo frame. Descriptions show when present.
5. **Paused ordering: one call bar.**
   - While `ordering_open` is off, cards show no "Customise when ordering opens" or "Ordering paused" control.
   - Instead there is ONE sticky bar: "Online ordering is paused. Call us to order for pickup. [Call to order (02) 9774 2286]" → `tel:+61297742286`.
   - The `[doughboss_menu]` shortcode renders the bar server-side, hidden when `DoughBoss_Settings::ordering_open()` is true.
   - The storefront's live `/config` read reveals or hides it, so cached pages follow the real state.
   - When ordering opens, the normal add-to-cart and customise controls return automatically.
   - The number comes from the new `order_phone` setting (Settings > Call-to-order phone).

### P1
6. **Header** (theme).
   - The header keeps one primary CTA: "Order now" when open, "Browse menu" when paused.
   - The launch bar now reads "Online ordering is paused — call to order or visit a shop · Call (02) 9774 2286". This replaces the duplicate "Browse the menu" link.
   - A nav item that links to `/order/` (the WP menu's "Order Online") becomes "**Call to order**" (`tel:`) while paused, via `wp_nav_menu_objects` and `nav_menu_link_attributes`.
   - Both variants are carried in `data-db-open-*` and `data-db-paused-*` attributes. `doughboss-shop-status.js` (`syncOrderingState`) switches them from the live `/config`, so the header reverts automatically when ordering opens.
   - `doughboss_final_ordering_open()` now prefers `DoughBoss_Settings::ordering_open()`.
7. **Mobile toggle.**
   - It is now icon-only: an SVG hamburger that swaps to an SVG X via `aria-expanded`. The existing `aria-label` toggles between Open and Close navigation.
   - The drawer close button is also an SVG. No raw "Menu ×" text is left.
8. **Hero motion control.**
   - "Pause photo motion" is now a 44 px corner icon toggle with pause/play icons, `aria-pressed`, and a label in `aria-label`/`title`. It is no longer a CTA pill.
   - It is hidden under `prefers-reduced-motion: reduce`, where the photo is static and the JS still reports "Photo motion off".
   - The helper caption is removed.
9. **Stat strips.**
   - The duplicate home strip (`.dbf-hero-stats`) is removed.
   - The hero's own strip is now a `<ul>` with separate value and label blocks and a real space between them, so text reads "Since 2009 In the industry".
10. **Wholesale / franchising.**
    - `[doughboss_b2b_form type="wholesale|franchise"]` (class `DoughBoss_B2B`) posts JSON to `POST /doughboss/v1/b2b/enquiry`.
    - Safeguards:
      - REST nonce
      - honeypot (`website`)
      - rate limit of 5 per hour per IP
      - full server validation: name; business (required for wholesale); email (rejects CR/LF and commas); AU-ish phone of 8–15 digits; message of 10–2000 characters
    - The enquiry is emailed to `b2b_email` (blank means `orders_email`, today info@doughboss.com.au) with `Reply-To: <name> <email>` (name sanitised for headers). Nothing is stored.
    - The pages are template-driven, so `template-parts/partner-page.php` renders the form automatically. If an editor already pasted the shortcode into page content, it is not duplicated.
11. **Footer.** "Partners" is now "**Franchising & partners**", and a "Wholesale" link was added. The fallback nav uses the same label.

### P2
12. **Store cards** (home and /locations/, `template-parts/locations.php`).
    - Each card has separate rows (Hours / Phone / Ordering), a "Call <shop>" `tel:` button and a "Google Maps" button.
    - Each card also has a live **Open now · until 2:30pm / Closed now · opens Tue 6:30am** badge.
    - The badge is calculated by `DoughBoss_Store_Hours::state()` in Australia/Sydney time. theme.js re-computes it every minute from the same `data-dbf-hours`, so cached pages self-correct.
    - Hours source: the shop's stored weekly hours (DoughBoss > Locations, matched by slug). When none are stored, the published hours are used: Revesby 7 days 6:30am–2:30pm, Bankstown Mon–Fri 7am–2pm, Roselands 7 days 8am–3pm.
    - **Note:** the stored weekly hours are the *pickup* hours table. If pickup hours ever differ from trading hours, the card follows pickup hours. Filter `doughboss_store_hours_use_stored` → false forces the published hours.
13. **Catering quote builder.**
    - Package cards show the size ("2 Dozen", split from the title), "Serves 8–12" and the price as separate badges, plus the package's "includes" text.
    - Each card has −/qty/+ steppers (0–50).
    - The quote is live from the server: subtotal (when it differs from the total), total, deposit (%), balance and a capacity note.
    - Server side:
      - `DoughBoss_Catering::normalise_packages()` and `quote_packages()` handle the selection. Only IDs and quantities are read. Names and prices come from the package posts, and the deposit uses the highest selected package deposit %.
      - The REST arg `packages` (`id:qty,…` on the quote route, `[{id,qty}]` on the enquiry route) feeds them.
      - A single `package_id` is unchanged, and one package at qty 1 is priced exactly as before.
    - Storage needed no schema change:
      - `subtotal`/`quote_total`/`deposit`/`balance` are the server figures.
      - `package_id` is the package when only one package type is chosen, otherwise 0. With 0, staff can still adjust the quote in the admin quote editor.
      - The notes start with a readable "Packages selected: 2 × … — $144.00 … Package subtotal" block.
      - The admin list, catering board and staff email show the package list (`package_label()`).
    - Pickup location:
      - The shop select lists only catering shops (slug `revesby`, filter `doughboss_catering_location_slugs`), so today it is a fixed "Pickup from: Revesby".
      - Delivery fields render only if `doughboss_catering_delivery_enabled` is true (default false).

## Skipped / deviations (with reasons)
- **Missing descriptions were not written.** The audit's suggested ingredient copy was not used, to avoid inventing ingredients. The description area stays empty.
- **No multi-store "call" bar.** The audit listed Revesby, Bankstown and Roselands numbers in the sticky bar. The task asked for one Revesby call bar, and that is what was built.
- **Catering pickup chooser.** Bankstown and Roselands are not offered, per the business rule.
- **Per-head overflow is not charged on combined selections**, because the customer chose the quantities. A single package at qty 1 keeps the existing per-head rule. The UI says the estimate is indicative and staff confirm it.
- **The audit's CSS token sheet and announcement-bar badge were not copied.** The existing theme tokens were reused to keep the design consistent.
- **The B2B form needs JavaScript.** It shows a `<noscript>` call/email message instead. A no-JS admin-post fallback was not added.
